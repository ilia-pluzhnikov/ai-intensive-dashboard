# Живой дракон — дизайн

Дата: 2026-10-05 · Ветка: `worktree-living-dragon` · Статус: согласован с Ильёй в чате

## Зачем

Дракон на треке — главный персонаж дашборда, а сейчас он почти статичен:
два разных рисунка (`Blood Dragon Sprite Base.png` 1024 px и
`Blood Dragon Sprite Attack.png` 1061 px, разные поза, масштаб и манера)
сменяют друг друга раз в 4 + 2 секунды, и при смене дракон «телепортируется».
Позиция считается один раз при загрузке. Спрайты весят 2,1 МБ при показе
на 160 px — заметно для учеников из России на слабом канале.

Цель: дракон живой и плавный, его атака привязана к данным (стреляет в того,
кого догоняет), а при открытии страницы гонка разыгрывается заново.
Берём пункты A + B + C из обсуждения; D (реакция на курсор) и E (окружение)
— вне этой итерации.

## Решение по графике

Не перерисовываем. Режем текущий `Base`-спрайт на слои и анимируем их
трансформациями — cutout-риг. Проба (scratchpad, 2026-10-05) показала:
при перехлёсте слоёв у суставов повороты на 5–16° в масштабе сайта швов
не дают. Перерисовка через генератор сменила бы узнаваемый образ и
рисковала бы несовпадением частей по стилю.

Недостающее — внутренность пасти и нижние зубы — дорисовывает скрипт
нарезки процедурно, палитрой самого спрайта. Codex (`go-codex`,
gpt-image-2) — запасной путь, если процедурный вариант смотрится плохо.

## Компоненты

### 1. Нарезка: `tools/dragon/cut.py`

- Python + Pillow. Вход — `tools/dragon/source.png` (бывший
  `assets/Blood Dragon Sprite Base.png`, переносится сюда: сайт его больше
  не грузит).
- Полигоны частей и точки вращения — константы в скрипте. У каждой
  подвижной части два полигона: `own` (вырезается из родителя) и `layer`
  (что несёт часть: `own` + перехлёст, заходящий под родителя).
- Части: `tail`, `body`, `mouth` (неподвижная внутренность пасти),
  `jaw` (нижняя челюсть + дорисованные нижние зубы по её верхней кромке —
  в покое их закрывают верхние зубы слоя `head`), `head`, `hand`.
  Для `tail`, `body`, `head` — ещё `*-glow`: только яркие неоновые пиксели
  части (порог по насыщенности и яркости) для световой волны.
- Все слои — на общем холсте, обрезанном по силуэту с запасом под
  повороты, в 2× от размера показа (ретина). Формат WebP.
  Цель по весу — до 150 КБ на все слои вместе.
- Скрипт генерирует `css/dragon-rig.css` (с шапкой «generated, do not
  edit»): размеры холста, `transform-origin` каждой части и положение глаза
  в процентах. Единственный источник геометрии — скрипт.

### 2. Риг и анимация покоя: `css/dragon.css`

Разметка (строит `js/dragon.js`):

```
.dragon (позиция на треке, left: N%)
└─ .dragon-rig (общий холст; .is-walking / .is-aiming / .is-firing)
   ├─ .part.tail       (+ tail-glow)
   ├─ .part.body       (+ body-glow)
   ├─ .head-aim        (rotate(var(--aim)) — наведение, с transition)
   │  └─ .head-idle    (keyframes покоя)
   │     ├─ .part.mouth
   │     ├─ .part.jaw  (открывается при .is-firing)
   │     ├─ .part.head (+ head-glow)
   │     └─ .eye       (свечение + веко; его rect — точка вылета луча)
   └─ .part.hand
```

Анимации — только `transform` и `opacity`, 60 fps:
- дыхание: туловище `scaleY` ~1→1.025 от ступней, период ~3.2 с;
- голова кивает в такт дыханию (±2–3°);
- хвост качается ±6° со сдвигом фазы, период ~2.6 с;
- лапа подёргивается;
- глаз пульсирует свечением, моргает примерно раз в 4 с;
- световая волна: `*-glow`-слои под маской-градиентом, маска едет от хвоста
  к голове; все glow-слои на общем холсте, поэтому волна непрерывна;
- `.is-walking` — тяжёлый шаг для интро: частый подскок туловища и кивок.

Дракон крупнее нынешнего примерно в 1,6 раза (сейчас сам силуэт занимает
~86 px из 160 px картинки, 77 % которой — пустой фон). После просмотра
Илья попросил на 15 % меньше: `DISPLAY_SCALE = 0.2125`, силуэт ~117 px
(в 1,36 раза крупнее старого). Дракон привязан к дорожке снизу
(`bottom`), поэтому при смене масштаба стоит на той же земле.

### 3. Лазер-охотник: `js/dragon.js`

Чистые функции (тестируются в Node):
- `pickTarget(candidates, eyeX)` — `candidates`: `[{id, x, state}]`,
  `x` — центр аватара в px трека. Исключаются `dropped` и `victory`.
  Цель — ближайший **впереди** глаза (`x >= eyeX`, минимальный `x`);
  если впереди никого — самый отстающий по прогрессу (`data-progress`, а
  не `x`: данные, а не пиксели; изменено 2026-10-05 по решению Ильи —
  раньше был ближайший сзади, то есть лидер); нет кандидатов — `null`.
  Тогда же исправлена вёрстка меток: раньше `translate(-50%)` центрировал
  аватар вместе с именем, и длинное имя сдвигало аватар левее его
  позиции на 16–68 px. Теперь на позиции стоит центр аватара, имя висит
  сбоку вне потока, с 75 % (`NAME_FLIP_AT`) — слева от аватара. Во время
  забега (`.running`) имя скрыто и проявляется при приземлении, иначе у
  лидеров оно ~1,2 с торчало бы за финишем (нашёл финальный ревьюер).
- `shotDelay(states, rand)` — пауза до следующего выстрела: 7–11 с;
  4–7 с, если хоть кто-то в `stressed` или `bitten`.

Цикл выстрела:
1. **Прицел** (~0.6 с): `--aim` поворачивает голову к цели (клэмп
   −14°…+6°), глаз разгорается, искры у пасти.
2. **Выстрел** (~0.7 с): `.is-firing` открывает челюсть; луч из центра
   `.eye` (его `getBoundingClientRect` уже учитывает все трансформации)
   в центр аватара. Луч — `div` в треке, `width` = расстояние,
   `rotate(atan2)`, белое ядро + розовое свечение, `mix-blend-mode:
   screen`; вытягивается за ~120 мс, мерцает, гаснет.
3. **Попадание**: `img` аватара получает `.hit` — белая вспышка и тряска
   (на `img`, а не на `.avatar`, чтобы не конфликтовать с
   `stressed-pulse`); разлёт 8–12 искр.
4. Голова возвращается, планируется следующий выстрел.

Анимации выстрела — Web Animations API; между выстрелами ничего не
работает. Скрытая вкладка (`visibilitychange`) — таймер снят, при
возврате — перепланирован.

### 4. Повтор забега: `js/dashboard.js`

- Трек рендерится с аватарами на `left: 0`, дракон и красная зона — на
  стартовых значениях; через двойной `requestAnimationFrame` выставляются
  реальные позиции под классом `.intro`: `transition` ~2 с, ease-out,
  задержка `var(--i) * 80ms` по порядку ученика.
- Аватары во время бега подпрыгивают (`.running`), дракон идёт
  (`.is-walking`), красная зона растёт вместе с ним.
- По окончании (`2000 + n·80 + 100` мс) классы снимаются, стартует
  лазер. Повтор — один раз за загрузку страницы.
- Старая смена двух картинок (`startDragonAnimation`,
  `DRAGON_SPRITE_*`) удаляется.

### 5. Общее

- `prefers-reduced-motion: reduce` — риг без анимаций, интро пропускается
  (сразу финальные позиции), лазер не планируется.
- `?now=YYYY-MM-DD` подменяет текущую дату в `getDragonPosition()` —
  посмотреть дракона в середине и в конце потока. Некорректное значение
  игнорируется. На проде безвреден.
- `assets/Blood Dragon Sprite Attack.png` удаляется; `Base` переезжает в
  `tools/dragon/source.png`.
- `index.html` подключает `css/dragon-rig.css`, `css/dragon.css`,
  `js/dragon.js` (до `dashboard.js`). Админка не трогается — трека в ней
  нет. Деплой не меняется: Action копирует `css/`, `js/`, `assets/`
  целиком, `tools/` и `docs/` в бакет не попадают.
- Никаких библиотек и CDN — всё на ванильных CSS/JS (доступность из РФ).

## Проверка

- `node --test` для `pickTarget` и `shotDelay`, без зависимостей
  (`js/dragon.js` экспортирует их через `module.exports`, если он есть).
- Локальный сервер + Playwright: скриншоты рига в покое и в позах,
  запись интро и выстрела, консоль без ошибок, режим reduced-motion.
  Сценарии «начало / середина / конец потока» — через `?now=` на копии
  живых данных в `live/data.json` (локально; `live/` в `.gitignore`).
- Ветка не деплоится (Action — только `main`); слияние в `main` — по
  команде Ильи.

## Вне этой итерации

Реакция на курсор и клик (D), окружение — сетка, марево, глитч, конфетти (E),
звук, движение дракона в реальном времени без перезагрузки, мобильная
вёрстка.
